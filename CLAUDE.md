# CLAUDE.md — context for Claude Code sessions on this repo

This file exists so a fresh Claude Code session has full context immediately. Read `GAIUS_MASTERPLAN.md` and `GAIUS_ROADMAP.md` in full before doing anything else — this file is a pointer/summary, not a replacement for them.

## What this project is

**Gaius**: an open-source reimplementation of *Caesar* (Impressions Games, 1992/93 DOS), in the spirit of Julius/Augustus for Caesar III. Sibling project to the **IGA** (Impressions Games Archive, a reference hub), which lives in a sibling directory, not nested inside this one, and vice versa (avoids `CLAUDE.md` context bleed across projects).

## Critical rule before touching anything

**No original game assets ever get committed to this repo.** See `GAIUS_MASTERPLAN.md` section 3 (IP posture). Every test/tool that needs a real Caesar file reads it from a directory named by the `GAIUS_TEST_ASSETS` environment variable, which points at the developer's own legally-obtained copy (e.g. from GOG). Never add `.VPX`/`.PL8`/`.P32`/`.256`/`EMPIRE2.*`/`.SAV`/`CSR.EXE` files to git — `.gitignore` already blocks the common ones, but check before any `git add`. **One deliberate exception (decided 2026-10-03):** the few gameplay screenshots in `docs/images/` that the README shows -- captures of Gaius running the author's own copy, so they carry the original's art. Keep that set small; never add extracted files, sprite sheets or the game's full-screen pictures themselves.

## Current state (as of 2026-10-03)

Read `docs/CAESAR_CONSTRUCTION_DISPATCH_FINDINGS.md` sections 15, 16, 24, 25 and 26 before touching `systems/`.

- **Real saves (2026-09-12).** Fixtures live in `GAIUS_TEST_ASSETS/gaius_test_saves/` (`CAESARXX`, `WX`, `VX`, `UX.SAV`, in play order; a second session on 2026-09-14 added `CAESARXW`-`XQ`, a new city with reservoirs, working fountains and grades up to `0xD2`, all a year or more apart — findings section 23) — outside the game's own save directory so replaying the original can't overwrite them, and never in the repo. They proved `model::load`/`serialize` byte-identical against engine-written files; every Phase 5 footprint as a clean rectangle of its transcribed size, which confirms the row-major grid; and the save *writer*'s real global-word order. `global_words_128` is not a descending DS range: the old formula was wrong for 107 of 128 words. The exact table is `formats::save::kGlobalWordDsAddress` (treasury = `DS:0x6CA2` = save+`0x3E`).
- **`systems::service` re-transcribed from the disassembly (2026-09-13)**, proven by `test_save_corpus_simulation`. The corpus tables it had been built from were wrong in several ways. Five handlers had wrong parameters *and* names (`0xEE` is Prefecture, `0xEF` Barracks, `0xF3` Heavy Industry, `0xF4` Market, `0xEB` Oracle). Land value ceilings aren't a universal 31, and they act as a **per-cell running minimum** (`ServiceState::land_value_ceiling`). The unrest propagator has **no floor** — the -8..+50 clamp is a separate per-cell routine, `evolve_unrest`. Tiles `0x3C-0x3F` have no unrest effect; temples v1-3 do apply land value; and nine handlers existed that Gaius lacked (housing tiers, temple stages, negative-land value tiles). `tools/sim_check <save>` prints the cell-by-cell comparison with per-quarter and per-tile breakdowns.
- **Two adjacent tile tables, not one.** The monthly service scan (`0x2BBBB`) dispatches `DS:153A` for tiles above `0x35`; the housing development pass (`0x294CF`) dispatches `DS:1212` for tiles `0xC8` and up. `DS:1212`'s entries for `0xCA`-`0xFF` are the memory earlier RE read as "`DS:153A` tiles `0x00`-`0x35`" — so `0x297AC` is housing tile `0xCA`'s handler, not dead tile-`0x00` code, an error this file briefly repeated before findings section 16 corrected it. Tiles `0x00`-`0x35` are still never simulated; in real saves they are static terrain.
- **The month is 106 steps.** Steps 0-99 run the housing pass on one row each; steps 100-105 reset, compute population and water, and run the four service scans; then the calendar advances (month `DS:0x6C1C`, year `DS:0x6C32`). Houses react to last month's services.
- **Housing (2026-09-13).** Grades `0xC8`-`0xD7` promote and demote on land value, service bits (water `01`, `02`, market `08`, bath houses `04`, school/hospital `40`, entertainment `80`) and population units, merging into pairs, 2x2 and 3x3 houses. Population is 4x the per-cell table at `3496:007E`. (The RNG, the fountain pipe trace, the rioter that `unrest_collapses` spawns and the `0xA8`-`0xB1` burning tiles came later: `systems::month`, `service::apply_water`, `systems::actors`, findings section 21.)
- **Forum, Workshop, water, economy (2026-09-13).** Tiles `0xE0`-`0xE7` are the Forum's eight grades (the corpus called them temples; `service::apply_forum`), `0xF5`/`0xF6` are workshops and `0xEF` barracks, each with a record table the save keeps (`table_480`/`table_720`/`table_120`) — `construction::place_forum`/`place_workshop`, and the `model::CityState` overload of `clear_area` removes records on demolition. The water pass is exact, with the fountain pipe tracer (`service::fountain_supply`). `month::run_economy` transcribes step 101's four economy routines, which set the housing land value and unrest growth bases; recomputed from each real save's inputs it reproduces all five outputs in all four saves. Findings section 19.

Full derivation in `docs/CAESAR_CONSTRUCTION_DISPATCH_FINDINGS.md` sections 1-14, including all the dead ends — the failed passes are kept because the reason they failed is the transferable lesson.

### What's implemented

- `formats/` — VPX, P32, .256, PL8, EMPIRE2, SAV (read-only), EXEPACK decoders. All tested against real files where available; see `docs/FORMATS.md` for exact status per format, including novel RE findings made while implementing (PL8 container header, PL8 trailing-placeholder-frame pattern) and — added in Phase 5 — the old sprite gap, **closed 2026-09-13 by real DOSBox screenshots** (`GAIUS_TEST_ASSETS/gaius_test_screens/`, never in the repo): PL8 pixels are **four interleaved streams** like VPX (the original row-major decoder was wrong; frames now match the screenshots pixel-exact), the city palette is **`SHADE.256`** (all 256 entries), and `FONT1.PL8` decodes to a legible font. The same screenshots show the game loads `.P32` as nibble × 4, and `formats::p32` now does too (it used `n * 17`); `EMAP2.VPX` matches the map screenshot outside the game's overlay. `.256` is traced in `CSR.EXE`: the file goes untouched to the VGA DAC.
- `model/` — `city_state.hpp`/`.cpp`: `CityState`/`CityMap`/`Actor` (Layer 2, Phase 2). Reshapes a loaded `SaveFile` into typed fields for the parts of the save format that are understood (5 city grids, actor table, embedded EMPIRE2 map); the other 13 of 20 blocks are carried as byte vectors, and what each holds is identified from the save writer (dispatch findings section 22) — code reads them through `model::global_word` and the record offsets.
- `systems/` — Layer 3. `service.hpp`/`.cpp`: **transcribed directly from the disassembly and validated cell-for-cell against real saves** — read its header before changing anything. The three propagators (`apply_land_value` with the running-minimum ceiling, the floorless `apply_unrest`, `apply_flags`), `reset_tick`, `derive_network_flags`, `evolve_unrest`, `apply_water`, `rebuild_services` (one month-end: reset, water, full dispatch), the confidence-labeled `kC9D4BitTable`, every `DS:153A` handler, and `dispatch_tile()` with the engine's <= `0x35` gate. `housing.hpp`/`.cpp`: see above. `month.hpp`/`.cpp` (2026-09-13): the simulation clock — `run_step`/`run_month` in the engine dispatcher's order, the calendar, and the exact random number generator (`Random`); read its header for what a month does and doesn't yet include. `actors.hpp`/`.cpp` (2026-09-13): the walkers — the allocator, the per-tick update, movement around obstacles, the city behaviour states and the forum/workshop/barracks spawners (dispatch findings section 20); `run_step` on a whole save ticks them. `construction.hpp`/`.cpp` (Phase 5): the 34-entry command table plus `placement_spec`/`can_place`/`place`; `place` writes each footprint cell's part index (`4*dy + dx`) into `7BB4`, as the engine does. Six of the 23 placing commands are `DragAutoTiled`/`VariantSelected`, and `place` returns false for them by design. `economy.hpp`/`.cpp` (2026-09-14): the treasury — construction costs, the population and industrial taxes, and the year's settlement with operating costs and the tribute to Rome; `run_step` runs it when the year turns, and it reproduces every save's last year of accounts (findings section 25). `military.hpp`/`.cpp` (2026-09-14): the Legion — regular Centuries from the army wages, irregular from population and conscription, and their yearly assignment to the Cohorts (type-13 actors); `run_step` runs it after the histories (findings section 26).
- `render/` — `city_render.hpp`/`.cpp` (2026-09-13): draws the city view exactly as the original does, from `FIXTS.PL8`/`HOUSES.PL8`/`HOUSES2.PL8` and `SHADE.256`, into an indexed image (no SDL). Transcribed from the engine's draw loop and checked pixel-exact against DOSBox captures — read `docs/CAESAR_CITY_RENDERER_FINDINGS.md` first. `gaius_viewer` shows it as the first save view when it finds the game's files (`--assets`, or beside the save). It also draws a save's walkers (`MOREMEN.PL8`, from the actor table at `DS:0x5D84`) between tile rows, as the engine does — findings section 8. The save writer's address map for every save block is in `docs/FORMATS.md`.
- `platform/` — `window.cpp` (SDL2, logical-resolution framebuffer + letterboxing, windowed/borderless/fullscreen, vsync), `input.cpp` (unified mouse/touch/gamepad command stream: rebindable keys and buttons, touch gestures built from finger events, gamepads opened and polled), `paths.cpp` + `path_rules.cpp` (Gaius's settings/saves/game folders per OS; the rules are SDL-free and tested), `game_import.cpp` (Android's folder import through `GaiusActivity`).
- `ui/` — Phase 5's toolbar, and deliberately free of both SDL and `apps/` (pure geometry plus pixel writes into an RGB24 buffer, so layout and hit-testing are headlessly testable). `metrics.hpp`/`.cpp`: four breakpoints, every size derived from one `scale`; the original's measured numbers (`kOriginalPanelH` = 24, `kOriginalIconPx` = 16) live here with provenance comments. `breakpoint_for()` takes a `has_touch` flag rather than guessing device class from resolution — an earlier size-only version classified the viewer's own 960×600 desktop window as a handheld. `toolbar.hpp`/`.cpp`: layout, hit-testing and rendering, where `render()` and `hit_test()` both go through one `button(i)` so a drawn button and its touch target cannot drift apart. Button icons are generated from `systems::construction::placement_spec` — the building's real footprint in its real map colour — rather than invented pictograms. `font.hpp`/`.cpp`: a 5×7 bitmap font that is **explicitly a placeholder, not the game's font** — the fallback when the user's game files aren't available. `game_font.hpp`/`.cpp` (2026-09-13): the game's own `FONT1.PL8` text, drawn through the engine's `DS:0F64` character table and matched pixel-exact against a capture; the toolbar label uses it when the viewer finds the game's files.
- `apps/viewer/` — `gaius_viewer`, an interactive pannable/zoomable viewer that handles both EMPIRE2 scenarios and `.SAV` files (dispatched by exact file size), which is the game: with no argument it finds the game folder or shows a setup screen (`setup_screen.hpp`); `settings_page.hpp` is the Settings screen. On Android the same `main.cpp` is `libmain.so` (`android/README.md`). Since 2026-10-03 also `cursor.hpp` (Gaius's own pointer), `overlays.hpp` (message box, plaque, type menus, minimap, build preview), `intro.hpp` (Gaius's title) and `original_intro.hpp` / `original_intro_run.hpp` (the original's opening); since 2026-10-09 `tutorial.hpp` (item 46).
- `audio/` — `ail_xmidi.hpp`/`.cpp`: the AIL 2.14 music driver (`XMIDI.ASM`, `YAMAHA.INC`) transcribed from its released source, producing YM3812 register writes; `game_audio.hpp`/`.cpp`: the game's sound layer (segment `31E0`) on ymfm's YM3812 and the Sound Blaster's digital channel, rendering samples without SDL (findings section 45).
- `tools/` — `fuzz_formats` (damaged files and saves through every decoder, the sound driver and the simulation; `docs/ROBUSTNESS.md`), `dump_vpx`, `dump_pl8` (also `.PL1`, a grid with `--cols`, every frame with `--frames`), `dump_vas`, `dump_voc` (an effect to WAV, as stored), `xmi2mid`, `empire_view`, `save_inspect` (block table, global words with their true DS addresses and names, actor table; `--summary` for scripts), `save_diff` (what changed between two saves), `bindiff_exe`, `sim_check` (reruns one simulation pass over a real save and compares it with the layers the engine saved; exit 0 on a match), `month_check` (finds the steps between two saves of one session and checks `run_step` reproduces the later one), `render_city` (draws a save's city with the game's sprites to a PNG), `render_audio` (a tune or effect, as the game plays it, to WAV), and `playtest` (a bot that plays a whole career through the real game logic, item 30; `playtest <game> tutorial` plays the first rank as the viewer's tutorial tells a newcomer to, item 46).
- `scripts/` — Python over the tools, for players, modders and contributors (`scripts/README.md`): `export_assets.py` (every picture, sprite, sound, tune and map; refuses to write game art inside the repo except under the git-ignored `export/`), `list_saves.py`, `render_saves.py`, `compare_saves.py`, `check_saves.py` (the simulation against any saves; `CAESARXS` and `CAESARXW` differ on its rebuild check by design — written mid-month), `record_session.py` (2026-10-09: while the owner plays, a timestamped copy of every save either game writes and the screen every five seconds -- DOSBox's own 320 x 200 screenshots for the original, whose Ctrl+F5 it presses only while DOSBox is in front, and `gaius_viewer --capture-dir` for Gaius; GOG's DOSBox writes the original's saves to `<install>\cloud_saves\US` and its screenshots to `<install>\capture`, beside its configuration file; `--video` adds a film of the two games' windows by OBS Studio 32, installed here on 2026-10-09, run on its own `Gaius-recorder` profile and stopped through a hotkey on F23; tested against DOSBox full screen with GOG's own settings and against Gaius. **DOSBox 0.74 dies if asked for a screenshot before its first frame** (`render.cpp`'s `RENDER_Init` leaves `render.updating` set with a 0 x 0 size, and libpng's error is fatal), so the key is only pressed once the window title reads `Program: CSR`), `extract_strings.py` and `test_scripts.py` (run in CI).
- `tests/test_formats.cpp` — dependency-free test harness (no framework), corpus tests skip cleanly without `GAIUS_TEST_ASSETS`.

### Notable RE findings made while building this (not just implementing already-known specs)

Addenda in `docs/` document genuine reverse-engineering work done as a side effect of implementation, not just coding against a finished spec:

- `docs/CAESAR_EXEPACK_AND_STRINGS_FINDINGS.md` — the EXEPACK decompression algorithm was fully derived from disassembling the actual embedded stub (`ndisasm`), since the main RE corpus only vaguely described it. Validated against two independent real `CSR.EXE` builds. Also documents a large set of previously-unextracted game text (full promotion-rank ladder, province names, cohort status words) found via `bindiff_exe`.
- `docs/CAESAR_GOG_BUILD_FINDINGS.md` — findings from a GOG digital distribution package (a second, international/multi-language `CSR.EXE` build exists; `COHORT.CSR` resolved as a runtime handoff artifact, not shipped content; a concrete entry point for the battle-resolution system was found via `CAESAR.BAT`'s launch loop).
- `docs/CAESAR_CONSTRUCTION_DISPATCH_FINDINGS.md` (Phase 5, 16 sections) — direct `capstone`-based disassembly of the decompressed US-build image, and the largest single block of novel RE this project has produced. **Both dispatch tables are now fully recovered**: `DS:153A` (flat `0x75D8A`, simulation — tile ID → per-tick behaviour) and `DS:127C` (flat `0x75ACC`, construction — command ID → placement handler). Also: the 34-entry command string table byte-exact, per-command seed tiles/footprints/terrain gate, the `0x36`-`0x40` auto-tiling mechanism traced deeper than `v1`/`v2` had, an off-by-one correction to `v2`'s entire published tile-ID table, three building re-identifications (`0xEB` Oracle, `0xEC` School, `0xEE` Prefecture), and the DS base (`0x74850`) and main simulation-tick dispatcher (`0x293A2`) found as byproducts. **The general technique is the reusable part**: scan for runs of ≥8 consecutive 4-byte entries sharing a segment word to find far-pointer tables, then `flat = segment*16 + offset + DS_base_correction`. Sections 3-6 keep every ruled-out approach on the record. **Section 15 (2026-09-13)** reads the service layer directly: the phased tick, the <= `0x35` scan gate, the three propagators, every handler's parameters in one table, housing located at `0xC8-0xD7`, and the 10000/10000 real-save proof. **Section 16** reads housing: the `DS:1212` table and the correction it forces to section 15, the 106-step month, population and water, and every development handler.
- `docs/CAESAR_CITY_RENDERER_FINDINGS.md` (2026-09-13) — how the city view is drawn: which sheet sits in which segment, tile → frame rules, the `3496:14B2` building metrics table, per-cell sprite slices and the rows above a footprint, and why `.PL8` pixels are four interleaved streams (they're unchained-VGA planes). Proven against real DOSBox captures.

**These should eventually be folded into the main RE corpus** (`CAESAR_REVERSE_ENGINEERING_COMPLETE.md`, maintained outside this repo) — they haven't been merged there yet as of this handoff.

## Working conventions established so far

- Confidence-labeling discipline carries from the RE corpus into code comments: anything built on less-than-DEFINITIVE findings should say so in a comment, not present false certainty.
- Format decoders throw on any structural inconsistency rather than guessing/silently producing garbage (see `FormatError` usage throughout `formats/`).
- Corpus tests (needing real assets) skip, never fail, when assets aren't available — keep this pattern for new tests.
- **Validate simulation work against real saves, not only against transcribed parameters.** Every handler bug fixed on 2026-09-13 passed its unit tests, because those tests encoded the same wrong corpus values; `sim_check` found them all in one run. More saves — another scenario, a later city — are the cheapest way to widen that net.
- Licensing: code is GPL-3.0-or-later (`LICENSE`), documentation CC-BY-SA-4.0 (`docs/LICENSE`). New source files get `// SPDX-License-Identifier: GPL-3.0-or-later` as their first line. Third-party code keeps its own licence.
- **Layer names are the original's.** `CityMap::land_value` is `A2C4` (the Maps panel's "land value") and `CityMap::unrest` is `54A4` (its "trouble areas", what collapses a low-grade house). They were `coverage` and `land_value` until 2026-10-02, names from the early research that the executable doesn't support; docs older than that, and the corpus in `E:\dev_res\ig_res`, still use them (dispatch findings header). The plebs' "coverage" is something else and kept its name.
- Cross-platform/QoL concerns (resolution independence, input abstraction) are architecture decisions made early (Phase 1), not deferred polish — see `GAIUS_MASTERPLAN.md` section 5a. Don't add mouse-only or fixed-resolution code paths "temporarily."
